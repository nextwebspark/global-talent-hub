Fix 1 — Deduplication of same-company variants

Before persisting any company, strip common page-level prefixes from extracted names: "About Us -", "Employee Directory -", "Contact -", "Home -", "Services -", and any string that ends with a URL path pattern. Then deduplicate on the normalised name using fuzzy matching (not just exact string match) so "Majestic Stores TRD.CO." and "About Us - Majestic Stores" resolve to the same entity and only one is kept.

Fix 2 — Universal scoring via full intent context (the architectural fix)

Rewrite the Claude enrichment prompt to evaluate every company against the full extracted intent — sector, commercial role (distributor/manufacturer/retailer/operator), geography, and original query. Add the TA framing instruction. The prompt must check both sector match AND business function match independently. A company in the right sector but wrong function (restaurant in an FMCG distributor search, retailer in a manufacturing search, law firm in a fintech search) must return sectorMatch: false and confidenceScore below 40. This is a universal fix — no hardcoded industry rules needed. The commercialRole field already extracted in Step 1 must be passed through to the enrichment prompt — currently it is not.

Fix 3 — Minimum result threshold with expansion logic

If validated results fall below the number requested by the user, automatically trigger a second search round with broader query variants before returning results. For example if the user asks for 20 and only 11 pass validation, run additional queries like "consumer goods distribution {geography}", "wholesale {sector} companies {geography}", "{sector} supply chain companies {geography}". Keep expanding until the requested number is reached or all query variants are exhausted. Never return fewer results than requested without at least attempting expansion.

Fix 4 — Company name sanity check

Before persisting any company, validate the extracted name against these rules: must be under 60 characters, must not contain "companies in", "list of", "top", "best", "directory", "services in", standalone country or city names, or URL path fragments. Any name failing this check is discarded entirely — not passed through with a low confidence score.

Fix 5 — Fix the AI Suggested tab (currently showing 0)

The adjacent sector suggestion pipeline is not returning any results. This needs to be diagnosed and fixed — it is a core feature. After the primary search completes, the pipeline must run a second pass searching adjacent sectors inferred from the original intent, and populate the AI Suggested tab with those results. Adjacent sectors should be determined by Claude based on the search intent, not hardcoded. For each adjacent sector found, companies should be tagged "AI Suggested" with a rationale explaining why that sector is relevant to the original search.
