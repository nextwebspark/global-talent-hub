RIGHT-HAND PANEL (RHP) — MASTER INSTRUCTIONS
0. Purpose (Non-Negotiable)

The Right-Hand Panel is the single source of detail for the currently selected entity.

It must:

Always appear when something is selected

Never silently fail

Work identically whether selection comes from the map or the left panel

Remain stable across reloads, saved searches, and data edits

1. Scope of the Right-Hand Panel

The RHP supports two entity types only:

Company

Executive

It must switch content based on current selection type, not on where the click originated.

2. Visibility Rules (Absolute)

The RHP is hidden only when no entity is selected

Selecting a Company or Executive:

Instantly makes the RHP visible

Keeps it visible until selection is cleared

Visibility must never depend on:

Data availability

Hover state

Map zoom

Animation timing

Screen size

If the left panel shows a selection, the RHP must be visible.

3. Selection Authority (Single Source of Truth)

There must be one global selection state

Map, left panel, and RHP must all:

Read from it

Write to it

No component may hold its own copy of selection

Selection consistency overrides performance optimisation.

4. Render Contract (Never Silent)

When an entity is selected, the RHP must show exactly one of the following states:

Loading

Data available

No data available

Error loading data

Showing nothing is a bug.

5. Layout & Layering Guarantees

RHP must always render above the map

RHP must always have:

Non-zero width

Visible background

Scrollable content area

RHP must never render:

Behind the map

With zero width

Off-screen

If content exists but is not visible, layout is broken.

6. Component Lifecycle Rules

The RHP must remain mounted at all times

Switching selection:

Updates content inside the panel

Does not destroy and recreate the panel

Unmounting is not permitted except when the app itself is destroyed

This prevents race conditions and lost state.

7. Company View — Required Structure
7.1 Company Header (Sticky)

Always visible while scrolling.

Must include:

Company name

HQ country (city optional)

Sector / sub-sector

Ownership type

7.2 Scale Snapshot

Displayed as fixed KPI boxes.

Must include:

Revenue

Employee count

Geographic footprint (number of countries or regions)

Customer model (B2C / B2B / Mixed)

Rules:

Show “Unknown” if unavailable

Never hide the box due to missing data

7.3 Business Profile

Structured, scannable fields only.

Must include:

Core activity

Operating model

Primary revenue drivers

No long text. No marketing language.

7.4 Company Summary

Short narrative description.

Rules:

2–4 sentences maximum

Plain, factual tone

Descriptive only (no opinion)

7.5 Notes (User Editable)

Purpose: capture insight.

Rules:

Fully editable

Persisted to database

Visually separated from factual data

Never mixed with sourced data

7.6 Data Confidence Footer

Always visible at the bottom.

Must show:

Last verified year

Confidence indicator (High / Medium / Low)

8. Executive View — Required Behaviour

(Structure already defined elsewhere; included here for completeness.)

Header with name, role, company

Career history

Remuneration (collapsed by default)

Notes (editable, persisted)

Same loading / empty / error guarantees as company view

9. Reload & Persistence Rules

On reload or saved search restore:

Last selected entity must be restored

RHP must reappear automatically

Selection must not reset unless explicitly cleared by the user

10. Independence from Other UI

RHP must not:

Affect map visibility

Affect left panel expand/collapse

Change selection indirectly

Selection, visibility, and data are separate concerns

11. Error Handling & Trust

No silent failures

Every failure must be visible and explainable

Missing data is acceptable

Missing panel is not

12. Acceptance Criteria (All Must Pass)

Replit must confirm:

Company selected → company profile shown

Executive selected → executive profile shown

Map and list behave identically

Panel never disappears unexpectedly

Missing data shows a clear message

Notes persist across reloads

Panel always appears above the map

If any fail, the RHP is not production-ready.

Final Instruction to Replit

This panel is core infrastructure, not a feature.

Do not:

Add conditional shortcuts

Introduce alternative render paths

Hide the panel due to data issues

Optimise away stability

Build it once. Make it boring. Make it reliable.
